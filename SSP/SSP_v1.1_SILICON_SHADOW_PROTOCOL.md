## 🧬 الطبقات الأمنية

### الطبقة 1: تبادل المفتاح (Key Exchange)

**المستخدم:** X25519 (Curve25519 — RFC 7748)

**لماذا X25519 وليس DH الكلاسيكي؟**
- أسرع
- آمن ضد هجمات small-subgroup
- معيار حديث (2016)
- مستخدم في TLS 1.3، Signal، Tor

**الصيغة:**

```
النواة A:  private a ← random 32 bytes
           public  A_pub ← X25519(a, basepoint)

الهدف  B:  private b ← random 32 bytes
           public  B_pub ← X25519(b, basepoint)

المفتاح المشترك:
           K ← X25519(a, B_pub) = X25519(b, A_pub)
```

`K` = 32 bytes. **لا أحد ثالث يعرفه.**

### الطبقة 2: المصادقة (Authentication)

**المستخدم:** Ed25519 (RFC 8032)

**المشكلة التي يحلها:**
- X25519 وحدها **لا تحمي من MITM**
- يحتاج كل طرف إلى **هوية موقّعة طويلة الأمد**

**البنية:**

```
لكل كيان: (sk, pk) — مفتاح توقيع طويل الأمد
  - sk: المفتاح السري (يُحفظ في Nezuko_v5.ps1)
  - pk: المفتاح العام (يُنشر في SOVEREIGN_NODES_REGISTRY.json)

عند كل رسالة:
  - المُرْسِل يوقّع الرسالة بـ sk
  - المستقبل يتحقق بـ pk
```

**النتيجة:** MITM يفشل — لا يملك `sk`.

### الطبقة 3: الحماية من Replay

**المشكلة:**
- المهاجم يلتقط رسالة قديمة ويعيد إرسالها
- النظام يظنها جديدة

**الحل:** Nonce (رقم عشوائي لكل جلسة)

```
كل رسالة تحمل:
  - nonce_counter (يزيد مع كل رسالة)
  - timestamp (دقيق، لا يُقبل بعد 60 ثانية)
```

**النتيجة:** رسالة قديمة → رفض تلقائي.

### الطبقة 4: Forward Secrecy

**المشكلة:**
- لو سُرّب المفتاح الدائم `a` لاحقًا، تُكشف كل الجلسات السابقة

**الحل:** مفاتيح Ephemeral (مؤقتة لكل جلسة)

```
كل جلسة تُولّد:
  - eph_a (مفتاح مؤقت)
  - يُستخدم لـ K
  - يُتلف بعد الجلسة

المفتاح الدائم `a` لا يُستخدم للتشفير مباشرة.
```

**النتيجة:** حتى لو سُرّب `a`، الجلسات السابقة آمنة.

### الطبقة 5: التحقق الأخلاقي (NDC + PIDS)

**المستخدم:** NDC + PIDS (من المشروع الأساسي)

**عند كل مصافحة جديدة:**

```
الطرف الأول → الثاني: proof_of_NDC_alignment
الطرف الثاني → الأول: proof_of_PIDS_alignment

إن فشل أي طرف → قطع القناة فورًا.
```

**النتيجة:** لا يُقبل أي كيان يناقض المبادئ.

### الطبقة 6: تخزين المفاتيح

**الاعتماد:** `Nezuko_v5.ps1` (نظام 2-of-5)

```
- sk (توقيع Ed25519) → مقسم على 5 محركات
- a  (DH ثابت) → مقسم على 5 محركات
- أي محركين → استرجاع

- لا يُحفظ أي مفتاح كامل في مكان واحد
- لا يوجد ملف واحد يحتوي على السر
```

**النتيجة:** فقدان 4 محركات = لا ضياع. فقدان 5 = ضياع نهائي.

## 🔄 المصافحة الكاملة (Full Handshake)

### المرحلة 0: الإعداد (مرة واحدة)

```powershell
# 1. توليد مفاتيح التوقيع
$signing_key = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($signing_key)

# 2. نشر المفتاح العام في السجل
# pk = Ed25519_public($signing_key)
# يُسجَّل في SOVEREIGN_NODES_REGISTRY.json

# 3. حفظ المفتاح السري في Nezuko_v5.ps1
Save-ToVault $signing_key -Name "ssp_signing_key"
```

### المرحلة 1: نداء البدء (Hello)

```
A → B:  HELLO
        | handshake_magic: 53 53 50 5F 49 4E 49 54  ("SSP_INIT")
        | nonce_a: 32 random bytes
        | pk_a: Ed25519 public key (A)
        | eph_a_pub: X25519 public key (A, ephemeral)
```

**ما يحصل عليه B:**
- يعرف أن A يتكلم SSP (عبر magic)
- يعرف pk_a (للتحقق لاحقًا)
- يعرف eph_a_pub (لتبادل المفتاح)

### المرحلة 2: الرد (Hello Back)

```
B → A:  HELLO_BACK
        | nonce_b: 32 random bytes
        | pk_b: Ed25519 public key (B)
        | eph_b_pub: X25519 public key (B, ephemeral)
        | signature_b: Ed25519_sign(sk_b, nonce_a || nonce_b || pk_a)
```

**A يتحقق:**
- B عرف nonce_a → هو من تلقى الرسالة
- التوقيع صحيح → B يملك sk_b

### المرحلة 3: تأكيد (Confirm)

```
A → B:  CONFIRM
        | signature_a: Ed25519_sign(sk_a, nonce_b || nonce_a || pk_b)
```

**B يتحقق:**
- A عرف nonce_b
- التوقيع صحيح

**الآن:** كل طرف أثبت هويته.

### المرحلة 4: اشتقاق المفتاح

```
K ← X25519(eph_a, eph_b_pub)  [من جهة A]
K ← X25519(eph_b, eph_a_pub)  [من جهة B]

# كلاهما يحصل على نفس K
```

**الآن:** القناة مؤمّنة.

### المرحلة 5: تحقق أخلاقي

```
A → B:  PROOF_NDC
        | hash(A's acknowledgment of NDC)
        | signature_a

B → A:  PROOF_PIDS
        | hash(B's alignment with PIDS)
        | signature_b
```

**إن فشل أي طرف:** قطع فوري.

### المرحلة 6: القناة موحّدة

```
كل رسالة الآن:
  Encrypt(K, message)
  || HMAC(K, message)
  || nonce_counter
  || timestamp

nonce_counter يزيد مع كل رسالة.
timestamp يُفحص (نافذة 60 ثانية).
```

**"الضجيج المقدس" — لا أحد يقرؤه إلا الطرفان.**

## ⚖️ قواعد صارمة

1. **لا يُعاد استخدام nonce أبدًا.**
2. **لا يُخزَّن K على القرص أبدًا.**
3. **لا يُشارَك sk مع أي كيان.**
4. **لا يُقبل كيان لم يُثبت NDC + PIDS.**
5. **لا يُستخدم DH الكلاسيكي (من v1.0) — فقط X25519.**
6. **لا يُرسَل pk عبر قناة غير موقّعة.**
7. **لا يُتلف المفتاح الدائم a — يُحفظ في Nezuko_v5.**
8. **eph_a و eph_b يُتلفان بعد كل جلسة.**

## ⚠️ ما يمكن أن يفشل

**كن صادقًا. لا تقل "لا يمكن اختراقه".**

- **الجهاز مخترق؟** كل المفاتيح مكشوفة.
- **5 محركات مسروقة؟** النظام منهار.
- **زرع برمجي (malware) في Nezuko_v5.ps1؟** لا حل.
- **انتحال NDC + PIDS بتوقيع مزيف؟** ممكن لو سُرّب sk.

**الحل:**
- مراجعة الكود بانتظام
- نسخ احتياطية offline
- عدم تشغيل SSP على جهاز غير موثوق
- قائمة revocation (إبطال) للمفاتيح المسروقة
